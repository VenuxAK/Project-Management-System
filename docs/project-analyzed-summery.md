## 2. Architecture

### 2.1 Backend (Laravel)

```
Request → Route → Middleware (auth) → Controller → FormRequest (validation)
  → Service (business logic) → Model → Database
  → Response (Inertia page/redirect)
```

**Layers:**

- **Controllers** (7) — Thin HTTP layer, delegates to services
- **Services** (4 + 2 interfaces) — Business logic with DI-bound interfaces (`ProjectServiceInterface`, `TaskServiceInterface`)
- **Policies** (2) — Authorization via `ProjectAccessService`
- **Form Requests** (8) — Validation + authorization gates
- **Models** (5) — Eloquent ORM
- **Events / Listeners** (4) — Task assignment & status change notifications
- **Middleware** — Inertia request sharing (auth user + flash messages)

### 2.2 Frontend (Vue 3 + Inertia)

```
app.js → Inertia router → Page components → Layout (AdminLayout)
  → Feature components → Composables (CRUD logic) → Inertia form submissions
```

**Structure:**

- **Pages** (6) — SignIn, SignUp, Dashboard, Projects, Tasks, Members
- **Layouts** — `AdminLayout` (sidebar + header + content), `FullScreenLayout` (auth)
- **Composables** (7) — `useResourceManager` (generic CRUD), feature-specific managers, `useSidebar`, `useTheme`
- **UI Components** — Reusable `DataTable`, `Modal`, `Button`, form inputs, flash messages
- **Design System** — Custom Tailwind theme with Outfit font, brand colors, dark mode

## 3. Database Schema

```
users ──M:M── roles          (via user_roles pivot)

users ──M:M── projects       (via project_user_roles pivot, with role_id)
```

## 5. Authentication & Authorization

### 5.1 Authentication

- Session-based (Laravel `web` guard)
- Custom auth views (no Laravel Breeze/Jetstream)
- Routes in `/routes/auth.php`

### 5.2 Authorization (RBAC)

Two-tier permission system:

1. **Global roles** — Checked first; if user has permission globally, access is granted
2. **Project-scoped roles** — Checked if no global permission found; user must have the permission within the specific project

**Authorization flow:** `Policy → User::hasPermission() → ProjectAccessService` checks global role permissions first, then project pivot permissions.

All authorization is handled server-side via Laravel Gates/ Policies; frontend conditionally shows UI elements based on the authenticated user's permissions shared via Inertia.
